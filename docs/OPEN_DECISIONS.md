# Open Decisions — Do Not Assume These Are Settled

These decisions are intentionally left open. Codex should identify when one blocks implementation and present options with trade-offs instead of silently choosing a vendor or inventing capabilities.

1. **MVP cricket data and replay:** **Decided.** Use Cricsheet historical JSON 1.x data as the supported MVP source. At backend startup, persist every file in the local male T20 international archive as a historical completed match except `1001349.json` (Australia v Sri Lanka, 2017-02-17). Bootstrap that one source without deliveries and replay it when an authenticated fan opens its workspace. This supports repeatable development and demos; it is not a live commercial data-provider integration.
2. **Authentication and user identity:** **Decided.** Use Clerk for frontend and backend authentication. A verified Clerk session is required for user-facing match APIs and Socket.IO. PostgreSQL stores only stable Clerk IDs for viewer-session ownership; Clerk remains the source of identity/profile data. Health endpoints remain public; the one backend-constrained live simulation can be activated by any authenticated fan, with no admin replay/reset capability.
3. **Video synchronization and seeking:** **Decided.** Video seeking and actual video playback mapping are intentionally excluded from the product. Live fans prioritize the live edge and rarely rewind video during continuous play. Real-time video offset mapping adds disproportionate complexity (broadcast latency, ad splicing, stream drift, and licensing). The Smart Match Timeline focuses 100% on important match events, in-app scorecard/over navigation, and contextual AI citations.
4. **AI model/API configuration:** **Decided.** Use Gemini API from Google AI Studio (`gemini-3.5-flash` default model with `GEMINI_THINKING_LEVEL=MINIMAL` for low-latency requests) accessed via direct REST endpoints with native Node.js `fetch` and structured JSON outputs (`generationConfig.responseSchema`). Configuration is centralized and environment-driven (`GEMINI_API_KEY`, `GEMINI_MODEL`, `GEMINI_TIMEOUT_MS`, `GEMINI_MAX_OUTPUT_TOKENS`, `GEMINI_THINKING_LEVEL`). Gemini 3 models reject the legacy numeric `thinkingBudget` setting, so it must not be sent.
5. **Deployment target:** Choose AWS, Render, or another host after checking WebSocket support, long-running worker support, managed PostgreSQL/Redis, secrets, logs, and cost.
6. **Package manager and workspace strategy:** The initial foundation uses npm native workspaces because the repository was empty and npm is available locally. Revisit only if concrete workspace needs justify another tool.
7. **UI design direction:** **Decided for the MVP.** Use a restrained, mobile-first companion interface: a neutral surface, one cricket-green primary accent, system typography, clear hierarchy, generous spacing, and minimal reusable components. Prioritize semantic landmarks, visible keyboard focus, high-contrast controls, touch-friendly targets, reduced-motion support, and responsive layouts over a separate design system. Do not add a UI framework or icon library without a concrete reviewed need.
8. **Scope of simulated-live support:** Initial development coverage is male T20 international JSON. Phase 3 permits one active replay per API process, selected by `LIVE_REPLAY_FILE` and paced by `REPLAY_INTERVAL_MS`. Simultaneous replays are out of scope. A fan opening the selected match starts an idle/completed replay; other fans attach while it runs.
9. **Meaning of wall-clock recap:** **Decided for the MVP source.** Cricsheet JSON does not provide trustworthy per-delivery occurrence timestamps for “last 10 minutes”. Preserve the unavailable value and label any later time-window recap approximate; replay scheduling time is not historical event-occurrence time.
10. **Future live-provider evaluation:** A future live provider remains unselected. Evaluate access, coverage, revisions, player IDs, timestamps, latency, rate limits, licensing, pricing, and commercial/demo rights before adding one.
11. **Delivery idempotency and corrections:** Deferred from Phase 2 by decision. The domain records source references and rejects duplicate internal delivery sequences, but automatic duplicate suppression and provider-correction reconciliation must be implemented before any replay or live ingestion pipeline is enabled.
12. **Timeline rules:** **Decided for the MVP.** Use transparent deterministic rules: 50/100 batter and partnership milestones, an expensive-over threshold of 15 bowler-conceded runs, and a scoring-rate shift only when a completed over differs materially from the previous two completed overs. Revisit these thresholds only with representative replay feedback; do not replace them with model inference.
